# PR-2 container receiver API probes and finite index design

Read-only probes against Jedi 0.20.1 and the current graph, using synthetic captured strings, no imported/executed fixture modules. Reproduce with `PYTHONPATH=. .venv/bin/python review/parser-refactor/pr2_probe.py`. Raw `infer`, `goto(follow_imports=True)`, `get_references(include_builtins=False)` records including path/line/column are in `PR2_PROBES.json`; compact API output is in `PR2_PROBES.log`. `PR2_GRAPH.log` records the current actual graph target, uncertainty, and exact origin subscription for each read.

| Receiver case | Raw `infer` | Raw `goto` | `get_references` | Graph's source origin and target |
| --- | --- | --- | --- | --- |
| Global `registry={}`, writer/read `registry['go']` | `builtins.dict` instance at both sites | same `registry` assignment line 2 | declaration and both uses | origin at dict literal line 2; Jedi subscript target empty, custom target `target` |
| `first={}; second=first`; writer via `second`, read via `first` | `builtins.dict` both | `second` declaration line 3 versus `first` declaration line 2 | separate reference sets for the two symbols | graph unifies to `first` literal line 2; Jedi subscript empty, custom target `target` |
| Independent `left={}; right={}`; writer via `right`, read via `left` | same `builtins.dict` instance type both | distinct assignments lines 2/3 | separate symbol reference sets | graph read subscribes to `left` literal; no target (missing key), correctly excludes `right` writer |
| `from base import registry as alias`; writer/read alias | `builtins.dict` both | writer resolves `base.registry` declaration, **read points to later alias subscript mutation** in client line 3 | grouped references include base declaration, import alias, writer and reader | graph origin is base literal; Jedi subscript target `target` but graph keeps conditional/dynamic write unknown |
| `add(bucket): bucket['go']=target; add(registry)` | `builtins.dict` both | writer points to parameter declaration, reader to `registry` assignment | separate parameter and global reference sets | graph derives registry literal via actual argument; Jedi subscript empty, custom target `target` with uncertainty |
| `make(): return {}; bucket=make(); bucket['go']=target` | `builtins.dict` both | writer points to `bucket=make()` line 3, reader points to **mutation** line 4 | grouped `bucket` references, no returned literal | graph source origin is `make` return dict literal; Jedi subscript target `target` and graph retains write uncertainty |

These observations establish a narrow API boundary. `infer` reports the container *type* here, not allocation identity; equal builtins.dict results cannot distinguish aliases from fresh allocations. `goto` gives a declaration/binding location, sometimes a mutation site, not generally a canonical container origin. `get_references` enumerates references to a symbol/import grouping, not abstract heap alias equivalence: `first` and `second` are separate groups despite sharing one dict, and parameter versus actual global are separate. It can seed source discovery once for a binding but cannot by itself certify writer reachability or missing/future key membership. The import and returned-container `goto` outputs specifically rule out treating every statement location as an allocation.

## Finite PR-2 design (after PR-1 review)

1. **Separate target selection and source origin.** At a literal subscript callee, retain the already mapped exact Jedi callable target when available; source collection computes container origin/entry evidence without asking a second system to determine that call target. The observed global registration and alias gaps have empty Jedi subscript results, so retain finite custom slot association for these cases. Preserve actual unknown/write coverage for import, parameter and return cases; Jedi's target is not a completeness certificate.
2. **Index writer effects once.** Use captured AST allocations, exact binding/alias/import traversal and existing effect events to identify each observed writer receiver's origin set and stable write site. An indexed `(origin,key equivalence)` writer bucket plus per-origin dynamic-key range stores known associations. Jedi `goto`/references can locate source declarations but their result must be followed through captured assignment/import/argument/return source evidence; never equate `builtins.dict` or symbol reference grouping with origin. Phase 1 can admit simple literal allocations and aliases/imports with validated source path. Parameter and returned containers stay on the legacy path until explicit caller/return provenance is indexed; avoid a premature broad whitelist.
3. **Record reads even on misses.** A known read of `(origin,key)` subscribes to that entry's producer/membership and records its matching writer supports. A missing key records the same negative membership subscription so a future inserted writer invalidates it. Unknown key on known origin subscribes to the origin's range. Unknown receiver/source remains `UNKNOWN` with an identifiable universe watch. New/deleted writes emit exact membership and producer changes to indexed readers; old supports are retained for deletion invalidation. This supports local update selection without examining unrelated writers per read.
4. **Handle unknown writer receivers explicitly.** Keep uncertainty at the unlocated writer and its boundary/watch. Propagate it to a known read only when captured source, a call/argument/return relation, an alias relation, or a reproduced requirement connects the writer to that read's origin. An unknown writer is not by itself evidence that it aliases every known dict; do not mark all complete known reads `UNKNOWN`. A universe membership watch can trigger future dependency discovery when a new binding appears, without enumerating the unknown-writer pool at every read. If a tested case needs broad expansion, record the concrete connection and scope it to that boundary. Ordered/conditional effects and equivalent Python keys retain existing semantics.
5. **Admission measurements.** For each admitted case compare selected targets, unknowns, coverage receipts, `_unit_supports`, `_unit_subscriptions`, `_unit_writes`, analysis inputs/reads, and full versus incremental public semantics against the current path. Count internal writer index build separately from per-read candidate visits and output serialization. Grow unrelated fresh private writers 0/20/100 and confirm the exact-origin read's internal checks stay local while negative/future and unknown-writer invalidation tests still change the right reader. Do not claim the full 83-file runtime bottleneck from the earlier bounded profile; parser/frontend preparation dominated that partial observation, and its later container work was not isolated.

This is a design/probe artifact only. No PR-2 production or test change was made while PR-1 formal review runs.
