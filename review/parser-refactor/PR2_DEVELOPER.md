## Target versus source work

`Analyzer.tool_first_subscript` selects one exact mapped Jedi callable for a fixed-key literal dictionary read with a verified direct function source and no related write/escape event. It records the literal writer, exact origin/key read subscription, call-target support through Graph, source trace, write-source coverage receipt, analysis read/watch and value-flow witness. For both private and module-global literals, forced legacy comparison gives the same targets, completeness, unknown reasons, receipt, trace, unit supports/subscriptions/writes, input events, analysis reads/watches and value-flow. The admitted call does not invoke `container_slots` to rediscover its target. Missing Jedi targets, related writes, copies/unpacks, sequence indices, field/parameter/return-associated values and effect uncertainty still use finite association.

The source-origin index runs once per selected-owner context. It maps each actual subscript writer receiver to abstract container origin and indexes candidate scopes by origin, rather than unioning all uncertain writer scopes into every read. Simple literal/Name alias sources are located without inferring slot values or calling Jedi. Complex import/parameter/return sources are located in an isolated private mapping context; only a *matched* writer is re-resolved for its reader's actual provenance. Unknown writer identity remains a boundary/watch and does not make an unrelated known read unknown. Existing exact and negative entry subscriptions still select future writers. The writer index refreshes only after an actual selected-owner expansion that may change caller-origin evidence, not per read.

Private index preparation detaches the current read stack, suppresses its ledger writes, and pointer-swaps fresh contextual memo/query/trace/effect maps in O(1). ReceiverAccess shares existing immutable inventories through a private cache view and charges the same bounded access budget. Raw Jedi Names/errors are cached separately by capture/module/position/goto, so private and actual consumers remap/replay independently without a second Script API execution at that position. Real API calls and raw observation hits are separate counters. A test snapshots source ledgers, mapped query keys and memo before/after index preparation with imported, parameter and returned container writers; they are unchanged.

Container effect events are preindexed by scope and order. Inert function/class declaration bindings are excluded from container effect scans; decorator/default calls and class execution remain events. A read uses a binary-search prefix and the scopes actually tied to its origin. Source-only reads add their actual inspected scope/event counts to the same work counters. In module-global and local literal read probes with 0/20/100 unrelated fresh private writers, target and uncertainty stay fixed, writer index receiver count grows 0/20/100 as expected, while per-read candidate scopes and event checks stay constant. No inference is drawn from `builtins.dict` type as an allocation identity; the Jedi 0.20.1 receiver API probes in `PR2_PROBES.md` show that limitation.
