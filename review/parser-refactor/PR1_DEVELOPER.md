# PR-1 development summary: mapped Jedi lexical targets

Status: candidate implementation in the materialized source tree; no commit or push. This is a bounded parser refactor, not a claim that Jedi resolves all Python values.

## Change

`lct/python_analysis.py::tool_first_lexical` admits a call callee only when the non-goto Jedi observation has one exact captured callable definition and no uncertainty beyond the analyzer's existing generic `jedi-inference-not-exhaustive` marker. The callee is a plain `Name`; a bounded source-only walk finds one reaching definition, directly or through simple `Name` assignment aliases. It checks parameter shadows, local rebinding/deletion, decorators, class scopes, closure scope, multiple reaching bindings and cycles; these remain on the existing resolver. The walk records lexical input observations, association traces and memoized answers for later reference/caller passes. It never runs the old local target inference for admitted callees.

`lct/graph.py::Graph.build` queries Jedi first, uses this source-only path when admitted, and otherwise retains existing resolve/adjudicate. A `target_provider` decision distinguishes Jedi selection from legacy association, and the evidence role names lexical source recording rather than claiming an independent target check. The public `CALLS` target support, raw Jedi record, boundary mapping, completeness and downstream graph relations retain their existing machinery. New counters separately report admitted tool-first sites, lexical source visits and legacy site resolutions.

`lct/storage.py::_identical_capture` resets these work counters to zero on an identical reuse; `tests/test_changed_python_gate.py` checks the public build. In iterative owner expansion, the counters reflect source work across attempts in the shared analyzer, not unique final sites. They do not measure Jedi execution time or prove a whole-program speedup.

Container subscripts, return-valued callees, parameters, receiver attributes, decorators and all missing/multiple/conflicting Jedi results still use the old path. In particular `register('go', target); R['go']()` has a measured empty Jedi result but a custom target; `a()` before local `a=1` has a Jedi candidate and a proven Python unbound-local exception. No container writer scan was bypassed without preserving subscriptions/writes.

## Formal review 1 repair

Review 1 found `PR1-SHARED-SOURCE-REPEAT` (P2): twenty calls through one 12-link module alias chain each relocated the same source suffix; the root-owned independent test failed with twenty `reaching` calls per shared binding. `tool_first_lexical` now recognizes an existing proved source-only `memo` entry at the exact `(scope, AST id, before)` key and matching mapped Jedi target. A later call links its trace to that suffix and replays each relevant lexical input observation for its own consumer. It does not re-run `reaching` or perform another target inference for the suffix. The source-only key metadata records producer scope only for observation replay. An unrelated cached resolver value is never admitted as a source-only proof. During a fresh lookup, the `reaching` input event is attributed to the call's consumer, matching the legacy stack context.

The root independent test now passes: each shared module binding is located once. A new two-consumer parity test compares targets, source traces, unit input events, unit supports, analysis inputs and reads with forced legacy resolution. Separate first-to-second target changes, deletion before read, and 0/20/100 unrelated private writer growth preserve the expected targets/unknowns and constant source-only visit count; these are small full graph probes, not a substitute for the public original-nine test. The prior public alias first→second→first and old-view checks passed root preflight before this repair; the focused review1 repair run also included public owner and capture-reuse tests.

The fixed shared-source probe has **12 module reaching lookups total**, one per alias binding, plus 20 distinct root call lookups: **32** versus the review1 candidate's 260. `pr1-review1-fix-shared-count.log` retains the observed 20 sites, 12 module lookups, max one per source, 32 source-only visits and 20 tool-first sites.
