# Batch 2: bounded Jedi-empty source association

This supplements a **call site** only when `get_signatures` returns no names, no exception, and the sole mapped reason is `jedi-no-result`. The original raw empty observation remains in site evidence. A separate `source-association` entry identifies the captured producer owner and source location; the edge basis says it came from bounded source association. Nonempty Jedi observations (including multiple, abstract, external or unmappable results), errors, and ordinary unknown calls do not enter the lookup.

Supported source patterns are deliberately narrow:

- A final call through a literal exact key of one known captured dictionary allocation. The allocation is a stable module-level literal binding. A direct unconditional module-level subscript assignment through that allocation or its simple alias supplies a callable RHS only when `infer` maps one captured callable definition. Other exact/range writes, deletion, receiver rebinding and method calls on its known aliases prevent an unsupported conclusion.
- A simple writer function with one direct `registry[key] = fn` body statement. Its already observed Jedi call signature and source recorder's paired `actual-parameter` records associate **the same call site** with a literal key and callable argument. Only a direct, unconditional expression call with one exact matching key is used. The callable actual is separately inferred with Jedi. Other dynamic keys, competing writers, conditional calls, ambiguous parameter binding or missing source facts remain unknown. Key `'b'` cannot supply key `'a'`.
- A callback formal called inside its owning function. The function's accepted incoming call and Jedi signature parameters associate its exact actual expression with that formal; the actual is inferred with Jedi. In the registered composition, Jedi metadata from the already observed `execute` source Name supplies the parameters for the newly associated `registry['dispatch'](first)` call. An unproven or multiply supplied formal remains unknown.

The association is a captured-source relation, not a runtime execution or latest-write solver. It does not model arbitrary mutation, callable instances, descriptor effects, unpacked arguments, dynamic keys, escaped dictionaries, conditional/loop effects, or nested/indirect registration. It does not fill an empty result by spelling or by searching every function. Such cases retain their original Jedi unknown result. `complete` stays false because the final Jedi result was empty even when one bounded source association is recorded.

Cold builds use source records from their one captured analyzer. Selected-owner updates use current records and lazily read hash-checked, unchanged producer facts from the previous immutable sidecar, indexed by origin or formal owner. Rebinding uses exact source locations under identical producer bytes. Final consumer support directly names the original callable supplier. The old view remains immutable; the new version is compared with a fresh cold build in the focused lifecycle tests. Work counters separate `supplemental_calls`, `supplemental_source_query_entries` and `supplemental_metadata_queries_executed` from the main query entries and source goto executions.

Reproduced upstream observations and exact positions: `review/jedi-capabilities/observations.json` cases `dict_alias_write`, `dict_register_two_keys`, and `registered_callback_composition` under Jedi 0.20.1 / Parso 0.8.7. The case matrix and official API comparison in that directory distinguish these specific empty call observations from general language support. This approved bounded association does not turn those observations into a feature-wide limitation claim.
