## Root cause and repair

A selected module owner previously expanded every import requester file to all its functions, even when the module was selected merely because one function body changed. A namespace change also selected every sibling in an importing file. The old private import request/dependency records named only the source module, so they could not retain a sibling function's deferred import while recomputing another. A candidate-component membership difference independently pulled unrelated owners into analysis although it reflected traversal range rather than a semantic source dependency.

- Cold and warm import records now retain `source_owner`, statement line/column, alias ordinal and bound local name. The indexed `import_lookup_keys` entry joins its exact request by ordinal. For changed namespace/pin/package facts, it selects the importing execution owner and, for a module-level import, functions in that file that read the imported binding or a straight-line module alias. The cached AST supplies those uses; per-file owner maps and per-binding alias/read caches are built once. Reexport modules propagate their actual request-site closure. A mere provider body change follows recorded unit source/read supports and does not trigger namespace expansion.
- Retained import requests and import dependencies are filtered by their actual execution owner, then merged with selected owners' new records. Physical ordinal is canonically assigned in both cold and warm production persistence from source module and import statement location; no request or source support is discarded. Graph binding/lookup and call resolution do not consume ordinal for semantic decisions; SQLite reverse indexes refer to the newly persisted ordinal and are rebuilt consistently.
- Existing positive owner input events for retained owners are mapped to the current candidate-component membership without requerying those owners. The component scope table remains current while incidental candidate-range changes do not select unrelated functions. Partial initial analysis continues to expand along actual providing-module/import namespace paths when the earlier budget omitted a container subscription.
- Updated obsolete full-build fallback wording in `unit_incremental.py` comments. Explicit incompatible/corrupt evidence failure and immutable publication rules remain.
