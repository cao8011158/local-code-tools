# Indexed dependency snapshot slice — development report

The first persistence seam from `integration-plan.md` is implemented in `lct/storage.py` and independently exercisable by `tests/test_incremental_dependency_store.py`. It does **not** wire `file_incremental.local_graph`, change scheduling, skip `extract`, or claim local analysis. The staged copy has no local Git metadata; no push/commit was attempted, and the concurrent `graph.py` edit was not touched.

`storage.build` removes `_import_requests` from `Graph.build` private output when supplied and passes requests, nodes and edges to `split_graph`. On the existing atomic candidate, that routine writes indexed `import_requests` (including an unresolved module request and its exact source file) and `file_adjacency` once from actual edges. Ownership is derived from the fresh node catalog; direct cross-file edges and a `LOOKUP_IN` boundary source owned by a real `IMPORTS` requester can become directed file pairs when the target is captured. A boundary **target** cannot contribute a captured owner: two importers of `json` are not adjacent. Repository `CONTAINS` is excluded to prevent repository-wide fanout; same-file relations do not create adjacency rows. The old `split_graph` positional signature remains valid through optional trailing arguments, and missing request inventory or metadata migration without fresh nodes does not claim a dependency certificate.

`FileDependencies` opens an immutable read-only sidecar only when the manifest advertises `indexed-v1`, its artifact hash/size match, and both tables exist. `adjacent(repository,path)` uses the source composite primary-key index plus target composite index and returns both directions; `importers(repository,module)` uses the exact requested-module index. A legacy marker/table omission or mismatched sidecar integrity raises `ToolError` and must lead a future consumer to full fallback; no empty set is presented as a valid certificate.

First independent review found a P2 migration/restore regression: I originally put `dependency_store` inside `graph`, then removed it while migrating a sidecar without a fresh dependency inventory. The legacy migration contract compares and preserves the full graph record. The availability marker now lives at the **top level** of the snapshot metadata; `split_graph` removes any prior top-level marker and sets it only with fresh nodes and an explicitly present import-request inventory. It leaves `graph` content intact. `FileDependencies` reads the top-level marker. No migration or management assertion was relaxed.

Public synthetic lexical-only/offline builds verify old absent-module requests survive creation of the previously absent module, a resolved import is adjacent in both directions, unrelated modules do not join via `CONTAINS` or a shared external `json` boundary, and the old sidecar remains readable. A 35-unrelated-file fixture checks actual SQLite `EXPLAIN QUERY PLAN` for `SEARCH` on `import_request_lookup`, `sqlite_autoindex_file_adjacency_1`, and `file_adjacency_target`; this establishes indexed lookup, not total build locality. A copied sidecar with a dropped table and correspondingly updated checksum still fails closed. No embedding API or real data/service was used.
