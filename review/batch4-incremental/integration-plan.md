## Actual path and minimum seam

`storage.build` currently calls `inventory(c)`, `extract(files)` (all Python `ast.parse` via `python_nodes`, all Markdown), `embedding_texts`, then `Graph(nodes, asts, repos).build(query_reuse=reuse)`. Query reuse only skips certified `jedi.Script.infer` calls; `Analyzer.__init__` still writes every captured module to a private project, inventories all sites, and builds global contextual maps. The subsequent catalog node/posting/edge differences and `dense_update.write_partitions` are persistence/vector optimizations, not a local graph analysis path. Keep these as the full fallback and atomic publication path.

First implement a **separate, opt-in candidate preparation seam** before `extract(files)`, returning fresh nodes, necessary AST context, graph products and explicit `analysis_scope`, or a reason to run the existing full path. The caller must decide before globally parsing ASTs. Retain `inventory` and repository-wide snapshot calculation, source-fingerprint recheck, candidate validation, checksum sidecars, `prepare_only`/`on_candidate`, activation and recovery unchanged. Output serialization and catalog reconciliation necessarily scan all public nodes/edges: measure that separately from parsing/association/Jedi work. Do not present output-size work as local.

## Sequential implementation slices

1. **Persist actual indexed dependencies in `storage.split_graph`.** `Graph.build` now emits `_import_requests`, alongside `_import_dependencies` and `_query_observations`; `split_graph` currently consumes only the latter two. Add `import_requests` with indexed `(lookup_repository, requested_module)` and source module/file, including negative lookups; derive indexed `file_adjacency` from *actual* old graph endpoints and their file owners. Handle repository `CONTAINS`, boundary endpoints, `LOOKUP_IN` and removals explicitly. Preserve the old snapshot immutable. Validate schema, checksums, row ownership and completeness before considering local reuse; legacy sidecars fall back. Avoid a runtime whole-edge scan for each changed file. Coordinate with the pending graph edit rather than claiming its requests are already shipped.
2. **Introduce a captured-source preparation path.** Compute all repository snapshot IDs from the fresh inventory, compare per-file hashes against the verified old `files` inventory, parse changed Python/Markdown, and obtain unchanged node records from the old catalog. Recompute public `snapshot_id`/`version_id` using `extract.python_nodes.identity` semantics for unchanged Python declarations, validate stable logical IDs, parent/ordinal, source hash and spans. Do not deserialize AST with arbitrary pickle. There is currently **no persistent AST cache**: old catalog and `files` store text/JSON, not AST objects. If a selected local analysis needs unchanged Python context, parse those captured bytes in the same build; if the existing `Analyzer` needs all module ASTs for Jedi, its global project/site preparation remains measurable global work. A safe first local slice may therefore be Markdown-only or a demonstrably isolated Python fixture; do not call it no-global-AST until a narrowed analyzer context actually runs through the public path.
3. **Wire a conservative local analysis gate.** Start with a changed-file seed; use old indexed relations and requests plus new direct imports to find impacted modules, but do not use the full new graph as a scheduling oracle. Persisted `IMPORTS`/`LOOKUP_IN`, `CALLS`, `REFERENCES`, `CONTEXT_ENTERS`, `INHERITS`, `WRAPS`, explicit import dependencies and negative module requests are useful positive triggers. The draft's unconditional two-way `file_adjacency` closure can select an entire shared-helper component; its `module_paths` scan and `ast.walk` over a globally prepared AST map do not meet locality by themselves. V4's directional top-level function and `__init__` seeds are a bounded experiment (26/27 strict matches), not an admissible universal scheduler. Initially select only cases with an explicit finite dependency certificate and no uncertified cross-file/callback/parameter, dynamic lookup, ambiguous namespace, changed pin/runtime/config/program, missing old relation/request, analysis budget exhaustion, or unmatched old/new identity. All other Python changes run the existing full graph path. Do not suppress UNKNOWN or negative results to make a case pass.
4. **Reuse only evidence whose semantics can be certified.** The draft `_rebind_evidence` recursively changes dictionaries with `target` and `version_id`, but V4's same-file `Alpha.__init__` change leaves twelve old `version_id` leaves in `Beta`'s reused `resolution_decision.write_source_coverage`; target equality was insufficient. Define typed proof-reference translation against fresh node definitions, check deleted/renamed targets and every nested exported evidence shape, and reanalyze any uncertified owner. Recompute site IDs, `source_version_id`/`target_version_id`, edge IDs, counts, observations, dependencies and request rows; never copy an old completeness marker. The draft `_site_id` and `_rebind_edge` alone are not a certificate. Evidence-reuse development in progress owns this piece; integrate after its independent result rather than editing it concurrently.
5. **Connect the proven return shape to `storage.build`.** `file_incremental.local_graph` presently expects `file_adjacency` and `import_requests` tables absent from current `split_graph`, and returns six products rather than the current `(edges, info)`; no caller uses it. Resolve those contracts, ensure all `_query_observations`/`_import_dependencies`/`_import_requests` are consumed exactly once, and preserve graph summary and `GRAPH_SITES`/`SOURCE_FILES` validation. Log `analysis_scope`, fallback reason, parsed Python files, AST/project context files, selected sites, actual Jedi executions, associations, full-output rows and reused vs rebuilt dense partitions. Publication can stay the existing complete-version transaction; Neo4j projection remains separately gated, not evidence that graph analysis was local.

## Acceptance and limits

Use public `build(..., prepare_only=True)` or a disposable synthetic repository, plus forced full builds from identical captured inputs. Compare full node/edge/site records including versioned proof trees, targets, status, UNKNOWN, completeness, import requests/dependencies, sidecars and failure recovery. Exercise changed/add/delete module and missing import, callbacks, keyword/return forwarding, `__init__`, same-file unrelated class, Markdown-only, damaged old evidence, and unrelated-file growth. Record AST parses/project files and internal indexed reads separately from required complete output and comparison costs. Run no embedding API (`lexical_only=True`/offline test setup) and no real dataset or service. Keep a failing fixture and full fallback for unsupported cases. This is a proposed implementation sequence, not a claim that current graph relations already certify arbitrary Python-local updates or that the current draft works.
