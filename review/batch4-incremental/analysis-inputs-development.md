# B4-WIT-01 captured query input scopes

The source-only read audit identified a missing reverse witness for empty/failed Jedi queries and candidate context. This batch adds a narrower captured-input ledger, **not** a complete semantic read proof. `Analyzer.query` calls `AnalysisInputs.observe` before its ordinary query cache, reusable-query cache, Jedi success, no-result or exception branches. Only a graph-validated component with intact site inventory uses a component scope; otherwise the consumer records the capture-wide scope. This observes what captured input set was available to the query without changing target, `UNKNOWN`, raw Jedi, site trace or effect semantics.

The ledger stores one shared component ID from sorted module identities; members once per component, consumer once per scope. A separate 20,000-record budget covers scope+member+consumer rows, with atomic record addition and truncation. A cached component skips member enumeration, and counts are O(1) per new consumer; a 200-member/200-consumer test records 401 rows and rejects repeat enumeration via a guarded frozenset. This budget is independent of the existing analysis-read budget.

`Graph.build` exports `_analysis_inputs` after value-flow computation. `storage.split_graph` writes `analysis_input_scopes`, `analysis_input_members` and `analysis_input_consumers` to the private `graph-sites.sqlite`, with indexes by member `(repository,path,scope_id)` and consumer `(scope_id,repository,path)`. The manifest stores only schema 1, `captured-query-scopes-partial`, three counts and truncation. `FileDependencies` checks summary counts, schema/kinds, necessary columns/indexes, module ownership, orphan records, component identity/membership and budget. `input_scope_readers` uses the member index; `input_scope_watchers` reads capture consumers once. `prepare` retains its previous v6/value-flow/analysis-read gates, additionally fails closed on missing/truncated scope evidence, seeds capture watchers once and expands each changed producer through indexed component readers. Selected consumers' new scopes replace old rows; retained consumers must have verified unchanged endpoints and no selected component member or affected capture scope. Identical-capture reuse verifies and copies the rows. No rows enter public catalog, vectors, Neo4j or manifest graph status.

The initial local test attempt failed at collection because `lct.analysis_inputs` did not exist (`analysis-inputs-prechange.log`); this is a test scaffolding failure, **not** a public build behavior reproduction. The parent recorded independent old-build missing-evidence failures separately. After implementation, focused tests passed 7/7 (`analysis-inputs-targeted.log`), covering bounded ledger, empty/error/cache query, indexed persisted reader and 0/20 unrelated local/full three-table equality, old-view immutability, schema/count/truncation fallback and identical-capture reuse. Related historical tests passed 53/53 (`analysis-inputs-related.log`). The parent owns independent checks and formal review.

Limits: the new sidecar does not assert all Jedi internal reads, absent names or dynamic receiver dependencies; `analysis_input_coverage` deliberately remains `partial`. Six complex fixed state-machine files still fail v6 whole-capture certification. Local reuse continues to require all older gates and independent full-oracle equality for admitted captures.

After the final production edit, the one fast suite passed **625 passed, 27 skipped** in `analysis-inputs-fast-suite.log`. The parent-owned independent tests were not included in this count.

A final validation-locality correction followed that suite: `FileDependencies` now collects only module IDs actually referenced by scope members/consumers, fetches `node_id,repository,path` in 256-ID primary-key batches with `kind='module'`, and does not read or JSON-parse catalog `data` for every function node. An empty ledger makes no catalog metadata query. The new guard test intercepts the catalog SQL, rejects `data` reads/full scans, compares bound IDs with the ledger IDs, and checks an unknown module fails validation. Focused **8 passed** (`analysis-inputs-catalog-targeted.log`), related **56 passed** (`analysis-inputs-catalog-related.log`). The 625-test fast suite predates this narrowly scoped correction; the parent owns the final full gate.
