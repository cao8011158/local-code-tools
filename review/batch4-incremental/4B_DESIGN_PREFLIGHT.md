## 附录：passive-source 首切片提交前设计校验（4A 已由主 Agent 验收；非正式 4B review）

只读以固定 `lct-four-a-review` 的 Analyzer/EffectCatalog 语义为依据，并看了正在写入中的候选 `passive_python.py` /接线；未运行业务图或修改 worker 文件。该准入应定义为**未变纯源的旧语义事实为空，且本次选中复杂源全量重算**，不是把纯函数称作全图 `NO_EFFECT`。`python_effects.py` 134–163 对普通 `FunctionDef` 即使没有 decorator/default/annotation，仍在父 scope 产生 `binding` event；函数体的 `pass`/primitive `return` 不含调用、导入、成员/名字读取、slot writer，也没有定义期 implicit-call。`EffectCatalog.slot_scopes` 85–96 不会因此记录 writer；但不能以没有 `scope-execution` 事件或没有 CALLS 边推导函数名绑定无影响。`python_analysis.py` 776–805 的 `reaching` 可由函数名产生定义候选，1075–1090 的 `binding` 把它变成 callable，`inventory` 475–532 仍枚举定义/header/body；因此函数和模块必须在**完整 catalog 与捕获源码上下文**中可见，选中调用者才能重新解析，不能省去它们的定义节点或当外部。

当前候选 `passive_python.certify` 8–29 只容许模块开头一个 docstring、其后若干唯一的普通 `FunctionDef`（拒绝名字以 `__` 开头、decorator/返回与参数注解/default/type_params/posonly/kwonly/*args/**kwargs），函数内开头 docstring 后只容许 `pass` 或 `return` 六种精确 primitive Constant/裸 return。这个 guard 合理避开定义期执行和 AST 引用/调用；还须确保**目录级身份**不因新旧模块名/路径别名、包初始化器、跨仓库 pin 或 namespace 变化而漂移，且旧证书是同一冻结字节、policy、捕获配置/分析器版本可兼容；旧证书值必须与 catalog 文件 SHA、当前文件 SHA 一致。仅模块 basename 或 `module_name(path)` 相同不足以证明同一 capture。函数体中 docstring 可影响提取的 `docstring`/brief/definition_version，即使它无调用；旧节点按源码哈希核验后照旧重绑，不能丢弃或跳过定义输出。唯一名称 guard 避免同一模块函数覆盖；若跨模块或 Jedi path alias 产生同名，仍须按现有 `Graph.modules`/pin 的歧义门禁处理。

旧事实空检应逐个确认 passive 单元**双向**非 `CONTAINS` 边端点、sites/query observations/import dependencies+requests、analysis_reads 的 consumer、analysis_watches 的 consumer、analysis_input_consumers、value_nodes 的 owner、value_reads 的 consumer 为零；当前候选 `_passive_empty` 62–96 覆盖这些类别并 fail closed（实现上是扫描旧表，局部性成本尚待计量/索引化）。并应确认旧证书覆盖每个 retained 文件、侧车和 catalog 的完整性校验、节点/路径唯一、旧模块节点存在和旧源文本/哈希一致；对 value edges/reads 由 value_nodes 端点的完整性约束与 old snapshot 验证保证，不能只查单一 count。如果旧分析把 passive 当另一单元的**producer** 读取，即使它没有自身 consumer 行，源字节不变仍可让选中复杂消费者重算；但原有正向证据或全捕获 watch 必须使任何受影响消费者被选中，未选中旧消费者不得带跨 selected 边界证据。若出现旧 passive 节点为已观测 query target/非 CONTAINS edge endpoint，保守拒绝复用是合理的，不能删这些记录制造空白。

在候选 `python_incremental.py` 166–178，general 模式把所有非 passive 文件和变动文件选中；338–350 给 Graph 完整 nodes、挂载全部当前捕获源码，并在 `RequiredAnalysisContext` 下扩展该未计算路径、重建 Analyzer。`python_analysis.py` 141–190 的 `source_context` 确实为所有捕获模块写临时源并构建 Jedi project，但只有 `trees` 中模块创建 Script 和 AST 分析。`map_name` 586–590 对**已登记路径却未计算**的 Jedi 命中必须抛 `RequiredAnalysisContext`，`query` 768–774 必须先透传这个异常（不能吞为 `jedi-error`/`UNKNOWN`）；此原则也适用于其他宽 `except Exception` 包住 query/map_name/resolve 的入口。若 Jedi 的 `module_path` 是捕获内部别名、symlink/realpath 变化或无法与 `self.paths` 精确匹配，现有 591–606 会当 `external-or-excluded`，需额外验证全捕获路径登记的完备性/规范化与同名模块的确定解析；无法证实应回退。`module_path=None`、虚拟/第三方路径应维持原本 boundary/unknown，不应强行本地化。新 imports、缺失成员、module shadow、旧负查找仍不能靠 passive 语法自动排除，需由“所有非 passive 重算 + 旧事实空 + 完整 source_context + 严格 package/pin 门禁”共同保障。

**当前实现不能直接承诺此范围。** `graph.py` 160–177 总以整张传入的 Python AST 调 `simple_python.component_policy`；后者 547–550 在分组前先 `certify(files, asts, graph)` **整个捕获**。六复杂文件任一使该证书失败，full analyzer 的 `candidate_components=None`；`python_analysis.py` 225–238、372–404 于是把 `sites_for` 的候选范围放到全部 site，并保留无原子/未查询及潜在同名候选。general 候选 `python_incremental.py` 334–345 虽给 Graph 完整 nodes 与所有捕获源码的 Jedi 上下文，但 `local_asts` 只含 selected；在这份子图上重新 `component_policy` 甚至可能意外验证一个有限 v6 子集，造成**局部 analyzer 比 full analyzer 候选少**，其参数来源、回调、`UNKNOWN`、来源 trace 可变。完整 catalog/source_context 与 `RequiredAnalysisContext` 只能修复 Jedi 已命中路径，不能证明被有限候选排除的未查询复杂 site 永远不会影响 v6 函数。先确保 local 与 full 对每个复用目标使用同一候选 policy/范围；在现有 mixed-capture full policy 下应是 capture-wide，不能凭旧 v6 闭合继续限定。
