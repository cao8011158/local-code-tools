# Pinned Jedi 0.20.1 input footprint: real three-file capture

Source-only diagnostic, not an admission proof. `diagnose_jedi_inputs.py` copies the fixed SM `a7b0804` bytes of `item_units.py`, `_execution.py`, and `errors.py` into an isolated repository. It extracts those three ASTs and initializes `Analyzer` directly, without `Graph.build` or source execution. It calls `Analyzer.query` on the `data` Name and `re.fullmatch` Attribute within `valid_item_unit`, cold and then warm. Both child commands finished below 1 second under a hard 60-second limit:

```text
PYTHONPATH=. timeout 60s /workspace/scratch/413372d9a5a5/lct-round5-review/.venv/bin/python review/batch4-incremental/diagnose_jedi_inputs.py --noise 0 > review/batch4-incremental/jedi-inputs-0.json 2> review/batch4-incremental/jedi-inputs-0.stderr
PYTHONPATH=. timeout 60s /workspace/scratch/413372d9a5a5/lct-round5-review/.venv/bin/python review/batch4-incremental/diagnose_jedi_inputs.py --noise 0 --mutate > review/batch4-incremental/jedi-inputs-actor.json 2> review/batch4-incremental/jedi-inputs-actor.stderr
```

The second capture changes only the copied `_execution.py` string `"actor"` to `"actor_changed"`. Both captures produce `data` → no atoms/`jedi-no-result` and `re.fullmatch` → boundary `re.fullmatch`; the Analyzer's executed query count rises from 0 to 1 to 2 only on the two cold calls.

For cold `data`, the `_execution.py` tracked read SHA changed from `c48a9e63f3af9f4c…` to `b464042a1d6fd8c7…` while its `valid_item_unit` regex result stayed false; `errors.py` stayed `ba1bfb8988d9e297…` and false. The query **read bytes**, but this specific `_check_fs` decision used the name-filter result. Rechecking that predicate could be more precise than rejecting every source SHA change; if the identifier appears in either file, the old absence cannot be reused and the affected analysis must run. This does not prove that only this predicate suffices: `_search_function_arguments` is memoized, scans project files until a hit or `_OPENED_FILE_LIMIT`/`_PARSED_FILE_LIMIT` (2000/30, divided by five here), and the set/order of eligible files can change.

Pinned source entry points: `jedi/inference/__init__.py:201` (`parse_and_get_code`, direct code or `file_io.read`); `jedi/inference/imports.py:34–43` (`ModuleCache.get`), `:410,432` (`get_module_info` through compiled subprocess); `jedi/inference/dynamic_params.py:104` (memoized `_search_function_arguments`); `jedi/inference/references.py:273,300,168` (project module enumeration, `search_in_file_ios`, `_check_fs` token regex and conditional parse). The reusable instrumentation boundary would tag positive `(path,source hash)` reads and negative `(project root, file membership/order, identifier, regex result)` reads at the *actual decision point*, with cache entries retaining their original witness. `get_module_info` also needs search roots and positive/negative namespace membership, including absent modules; this run saw cache misses but no absent module resolution.

Gaps: monkeypatches do not see Jedi private caches, all filesystem existence/stat calls, compiled subprocess internal reads, plugin hooks, other `KnownContentFileIO` paths, or all parso cache hits. The 17 `path=None` parse events and typeshed/runtime boundary need better attribution before any certificate. Module/package membership, order, same-name shadowing, changed roots/pins and namespace additions must still conservatively invalidate or be independently proved; this probe saw cache misses but no absent module lookup. We did not measure 20 noise modules because the first 0-noise run already exposed the negative search and warm-cache loss; scaling and query-specific stopping order remain unmeasured. Original output was preserved as `jedi-inputs-0-initial.json` and `jedi-inputs-actor-initial.json`; corrected runs use `graph.repos` and label `_check_fs`'s returned context separately from regex matching on the *same* read bytes. No complete read coverage, local reuse certificate or performance gain is claimed. No production/Jedi dependency edit, full graph, paid API, installation or business execution occurred.
