# DICT-IMPORT-01 isolated parser repair

Baseline: isolated materialized copy of `agentic-trpg/local-code-tools` at remote commit `d455ec3710f3c3bc5ec385c76db94a8cc3ce38f9`, tree `c11e0b5edc81d902791b66168432ea7e9cf5a48f`, branch `feat/incremental-index-updates`. This is not a Git checkout. Only `lct/python_analysis.py` and `tests/test_dictionary_import_receiver.py` were changed in this isolated patch. Root's independent control `review/batch4-incremental/test_import_receiver_independent.py` was not edited.

The old `Analyzer.map_name` accepted exact captured `ast.Name` assignment targets when a Jedi `statement` result referred to an imported variable. For a captured `registry['go']=second`, Jedi `goto` can point at the `registry` token on this later subscript target. Before the repair, that exact token was marked `unmapped-captured-definition`, leaving the imported container origin unknown. The mapped Jedi inference of the eventual callable `second` was insufficient to certify the LCT association, yielding no public target with `unadjudicated-jedi-lct-conflict` / `unknown-container-origin`. This was independently reproduced on the isolated baseline (root's independent controls: 3 failed, 2 passed).

The fix considers only a captured `Assign`/`AnnAssign` target that is an `ast.Subscript` whose **immediate** receiver is an `ast.Name` matching Jedi's name, line and UTF-8 byte column. It collects matches before acting; a unique match resolves that receiver in its actual scope before the mutation statement, then accepts only one known, complete, finite `ast.Dict` container origin. An ambiguous, custom, sequence, unknown or cyclic receiver retains unknown; the old exact `ast.Name` assignment route remains unchanged. No call target is manufactured by token matching. The existing `container_slots` ordered writes and `Graph.build` adjudication produce the final target and uncertainty. No public graph schema, incremental certificate, Neo4j projection or search behavior was changed in this isolated fix.

After the fix, the direct and aliased import controls resolve the actual second target, and the Unicode receiver remains separate from another dictionary. Conditional mutation and custom `__getitem__` controls preserve existing uncertainty. Own tests inspect the exact mapping's finite container atom and cover later rebinding and excluded sequence mapping. The test command in `dict-import-receiver-targeted.log` ran own tests, root's independent controls, `tests/test_python_pipeline.py`, and `tests/test_python_review_regressions.py`: **106 passed**. `dict-import-receiver-ruff.log` shows Ruff passed for both modified files. No full suite, service, API, real repository build or publication ran in this isolated stage.

The repository-wide dictionary value-flow certificate and reverse-index update are separate pending work. This parser repair does not claim that merely adding container/entry graph nodes solves imported-variable mapping, nor that arbitrary dictionary aliases, dynamic writes and Python equality have become complete.
