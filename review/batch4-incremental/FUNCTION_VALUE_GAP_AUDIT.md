## Saved, but not selecting the affected closure

`lct/python_analysis.py::Analyzer.container_slots` records a `container-effects` module-to-module read for inspected writer scopes and a capture-wide `slot-writer-universe` watch for potential new writers. `lct/graph.py::Graph.build` exports `_analysis_reads` and `_analysis_watches`; `lct/storage.py::split_graph` stores them in indexed `analysis_reads`/`analysis_watches` tables of the private `indexed-v3` sidecar, marks `analysis_dependency_coverage=partial`, and exposes `FileDependencies.analysis_readers` and `analysis_watchers`. The read index is keyed by producer repository/path; the watch covers all captured Python. Truncation makes these APIs fail closed. See [incremental-update notes](../../docs/INCREMENTAL_UPDATE.md#partial-analysis-read-and-writer-universe-evidence) and `review/batch4-incremental/test_analysis_reads_independent.py`.

`prepare` reads old records, merges selected consumers and rejects unsafe cross-boundary retention in `merge_analysis_dependencies`; it **does not call** `analysis_readers` or `analysis_watchers` in its closure loop. This persisted subset maintains sidecar integrity but is not an admission certificate. Its current coverage is specifically container writer-scope inspection; it does not claim every dictionary key, negative read, callback, Jedi observation, argument flow or global lookup. `FileDependencies` validates the full sidecar checksum/integrity at construction and uses indexed lookups afterward; do not conflate that one-time validation with per-query scans.

## Confirmed absence at the persistent dependency layer

The catalog and `graph-sites.sqlite` DDL in `lct/storage.py`, and `Graph.build` output in `lct/graph.py`, do not persist separate dictionary/entry/write/call catalog nodes, per-entry producer-to-consumer reverse indexes, failed-key membership subscriptions, or a complete support graph for arguments, returns and closure cells. The analyzer has internal container origins, slots and `EffectEvent` records; absence of the proposed **persistent** model does not mean those analyses are absent. Current public graph relations include `CALLS` by owner and site, not a claim that each possible target is backed by a separately indexed assignment-to-argument-to-read path. `lct/python_incremental.py::prepare` has no general reverse dependency worklist or proof of unchanged downstream target/provenance facts for arbitrary Python.

## Not verified as absent; often covered coarsely or conservatively

Full analysis already handles portions of aliases, parameters/defaults, returns, lambdas, bound methods, decorators, dictionaries and callback association; tests in `tests/test_python_review_regressions.py`, `tests/test_python_review_round3.py`, `tests/test_python_call_access.py` and `tests/test_python_pipeline.py` exercise representative targets and uncertainty. `functools.partial` binding was not independently verified in this review. Existing `CALLS` and import/file adjacency may bring a producer into a certified component; changed Python outside that strict certificate falls back to full analysis. Do not call these influences categorically missing. The exact completeness of every dynamic descriptor, unknown equality, control-flow path or third-party callback was not proven by this documentation review. The contract requires explicit `UNKNOWN` and full-build comparison instead of extrapolating static precision.

## Next bounded implementation slice and gates

Start with a supported constant-key dictionary case: one known container allocation, one entry identity, multiple source-identified writes (including a conditional), one known-key read and one call site whose target comes from that read. Reuse the existing `EffectEvent` order/phase/conditional information and existing call-site evidence; preserve all reaching alternatives and `UNKNOWN`. Add a second aliased container reference and a separate container with the same key to verify shared versus isolated identities. A deletion and a new formerly missing key must invalidate through **old** read/membership evidence. Compare full and incremental outputs, including site/edge fields and provenance, and show an indexed reverse lookup remains bounded as unrelated records grow. Make Python-equal primitive key cases (`True`, `1`, `1.0`) an explicit key-equivalence gate before claiming exact storage identity. No arbitrary user `__eq__` execution.

Before adding persisted kinds or changing queries, decide schema and coverage versions, rebinding across immutable captures, old-version fallback, graph projection and existing search-level compatibility. Semantic storage/write/site nodes, if selected, do not automatically get embeddings or enter module/class/function search results; node-to-vector cardinality need not be 1:1. Preserve previously published versions and failed-candidate pointer behavior, dense reuse verification, unknown/boundary relations and optional Neo4j projection. Definition-time defaults, closure cells, bound instance methods versus normal class attribute functions, partials and decorators can initially remain conservative `UNKNOWN` outside the bounded certificate. A Neo4j migration and broad admission are separate gates.
