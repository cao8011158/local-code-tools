The most useful unified capture point is **the decision made at each read boundary**, keyed by the current `resolve` evaluation stack's consumer module plus a stable source location and lookup namespace. Record both successful inspected producer modules and a separate negative/prospective subscription for a name/member/candidate universe **before** returning a result, including the no-result/error branch in `query` and the considered-but-rejected branch in `candidate_sites`/`may_call`. `_record_scope_read` already supplies successful module identities; extend its sibling record path rather than deriving new evidence by scanning exported site text. `query` must record observed mapped targets and failure/boundary context on ordinary, in-memory cache and validated reusable-query hits; otherwise a cache hit silently loses the read path. `member` should record the requested name even when `reaching` returns none and the consulted base owners; `parameter` should record the caller candidate universe even when zero sites match, while preserving exact matched `parameter-origin`. If a lookup has no finite indexable namespace (unknown receiver, broad Jedi failure, unsupported dynamic binding), attach an explicit all-captured-Python watch and mark coverage partial/truncated rather than inventing a precise exclusion. Keep the current `UNKNOWN`, coverage, effect ordering and raw Jedi result unchanged.

One minimal end-to-end implementation slice is a **per-consumer-module analysis witness** for actual name/member/Jedi/candidate decisions in a selected closed case, with `(consumer module, source site, kind, namespace/member or producer module, outcome)` and a completeness/truncation flag bound to source hashes, policy and pins. Export it beside current reads, persist indexed producer and namespace/member reverse keys, then have `prepare` query old positive **and negative** subscriptions for changed/deleted/new producer identities, enqueue the affected consumers, and reject a retained witness that crosses the selected boundary or carries a broad unresolved watch. A candidate can be admitted only if every retained unit has complete compatible coverage and independent fresh full records match, including sites, `UNKNOWN` and provenance; older schema/partial/over-budget evidence falls back. This slice needs a real consumer in `prepare` and old-view failure/retry checks. Adding rows alone would repeat the existing partial-ledger limitation.

The six added real-source files map to these paths without being analyzed: `service.py` has many inherited members, decorators, parameters and calls; `world_containers.py` has field/descriptor, container and writer paths; `item_package.py` has dict/argument/return paths; `combat.py` has imported/Jedi-boundary and exception paths; `_execution.py` has enum/member and conditional value paths; `dnd_runtime.py` is a reexport/import lookup. This is a syntax-to-entrypoint map only. Their whole nine-file capture remains outside v6 certification; no actual read set, candidate count or full-oracle equality was measured here.
