## Contract and failure behavior

`lct/evidence_reuse.py` creates a `RebindContext` once per capture pair. It indexes unique `(repository, path, complete qualname, kind)` identities and memoizes each definition check. A retained owner must be outside the scheduler's selected paths, retain its identity, AST, fingerprint, and exact source span. Each typed referenced definition must also retain these properties. The old record's `version_id` must match that old captured node. Only recognized `definitions` target/version pairs, `definition-dependencies` function/version evidence, and exact captured Jedi raw definition mappings are rebound. The raw mapping additionally validates its old `source_sha256` and copies the current source fingerprint. A deep copy leaves the old record and any opaque text intact; no global string substitution occurs. Unknown reference schema, mismatched stamp, missing/deleted/renamed/changed/relocated definition, or selected owner raises `EvidenceReuseRejected`.

V5 takes the v4 scheduler's selected paths, globally captures old/new node and AST catalogs for validation, and preflights old unselected CALLS edges and site records against that context. Rejected owner paths join the selection **before** `selective_build`; that pass uses the real Analyzer over the resulting selected paths. Candidate selection and rejection do not consult the fresh-full oracle. A tampered retained site integration test confirms that `c.py` is reanalyzed and matches a fresh build. The helper tests also exercise both nested typed record shapes, raw mapping and source hash, immutability and opaque text, tampered stamp, missing/deleted/changed/relocated reference, unknown shape, selected owner, and no node-table scans or repeated AST checks after index preparation.

## Cost and limits

The helper's context indexes **every old and new node once**, and the v5 candidate adds **all old + new AST captures** beyond v4's global summary preparation and selective graph capture. The same-file case has five memoized definition checks across retained records. These costs are not local parsing. In the 21-file shared-helper fixture, a changed `helper` AST is itself a referenced definition, so the required fail-closed rule rejects reuse of all 20 consumers: v5 selects 21/21 files, analyzes 20/20 outer sites, and makes 40/40 candidate/full graph Jedi queries. This is an honest lost v4 saving, not an unexplained performance claim. The 30 unrelated-file constructor probe still selects only the two related files, although its preparation captures 32 old and 32 new AST contexts twice (scheduler and evidence validation), followed by a 32-file selective graph context and global non-CALLS passes.

AST and span equality are necessary checks, not a complete transitive semantic dependency proof. V5 relies on the v4 scheduler's bounded owner-invalidation assumption; its unknown method effects, missing old CALLS edges, dynamic resolution, identities, and arbitrary dependencies remain unproved. It also reuses opaque old edge/site/public IDs and only normalizes selected semantic fields in this experiment. Identity/provenance schema rebinding beyond the typed definition references is not implemented, so this is **not production-wiring evidence**. A production integration must define an invalidation certificate and ID/publication semantics before storing reused records.
