# Batch 4: incremental analyzer identity and dependency design

Target baseline: `fc857f395a381e5dfec9941d60ca685bcbe0b3fd`, intended merge target `feat/local-code-tools-import`. This is a static diagnosis of the staged source copy, not a diff verified against a Git checkout. No full graph, paid API, or parser replacement was run. This report does not certify an incremental implementation.

## Current observable contract and analysis path

`storage.build` calls `inventory`, `extract(files)`, then `Graph(nodes, asts, repos).build()` before using SQLite node/edge content differences. The latter are persistence differences, not analysis reuse. `extract.extract` hashes all included `(path, text hash)` pairs per repository to produce `snapshot_id`; `python_nodes.identity` folds it into every Python node's `version_id`, while `Analyzer.site` folds it into each `site_id`. A Markdown-only edit thus renumbers the Python definitions and sites in that repository even when their source bytes are unchanged. `Graph.add_edge` embeds `source_version_id` and `target_version_id` before hashing the whole edge into `edge_id`. The stable logical `node_id` does not imply stable versioned evidence.

`Analyzer.__init__` creates private captured source files, a Jedi project and per-module `jedi.Script`, all AST ownership/module maps, site/reference/import/inheritance inventories, `EffectCatalog`, and `ReceiverAccess`. Its `query` cache is keyed by `(module ID, end line, end byte column, goto)` and contains mapped `Result` plus raw observations. Its `resolve` memo and `dependencies` use `id(expr)` and scope. `explain` follows only those recursive resolution dependencies; they are diagnostic traces, not complete persistent input dependency records. `ReceiverAccess.summary` has a version-bearing summary, but its cache is analyzer-local and it reads call/lexical/effect state. Neither this cache nor `EffectCatalog` supplies a complete reverse dependency graph.

`parameter` and `registry_arguments` enumerate `candidate_sites`, then apply `may_call` and exact `resolve` target checks. `candidate_sites` includes same-spelling sites, cached exact-target observations, observations with no atoms, and unqueried sites; during an in-flight query or changed inventory it falls back to the full site list. This is a within-analysis optimization, not a durable dependency index. Method receiver fallback additionally scans all `self.sites` for class construction. A new alias/callback call can alter an unchanged callee's parameter, registry slot, field effect, and ultimately another site. `name`/`reaching` and `member` also depend on the *absence* of earlier local, class, and imported bindings. `query` maps Jedi definitions against the current complete captured module/path index and may return `jedi-no-result`, errors, or non-exhaustive inference; a previously missing import is not stable under added modules or definitions.

## A. Keep public repository-wide identity, add a private semantic reuse key

The private key would include per-file captured bytes, parser/analyzer/program and relevant config versions, source path/module identity, dependency-pin state, and a separately proven dependency closure. It must not replace public `snapshot_id`, `version_id`, or `site_id`. For reusable computation, reinstantiate or translate AST-associated values in the *new* analyzer, then publish new snapshot-bound records. Pure same-file parse reuse is plausible, but `id(expr)`-keyed memo/requirements/coverage cannot be transferred directly. Even unchanged source in a changed repository requires a new public identity and evidence serialization.

At minimum the publication layer must regenerate or verify:

| Evidence | Where made / consumed | Rebinding requirement |
| --- | --- | --- |
| Node `snapshot_id`, `version_id`, `source_sha256`, parent and `resolution_parent` | `extract.python_nodes.identity`; `Analyzer.map_name`; SQLite nodes; Neo4j node projection | Recompute from new repository capture and current AST position/fingerprint. Keep logical IDs only when definitions and ordinals still denote the same declarations. |
| Site `site_id`, lexical/execution owners, position/phase, targets, UNKNOWN, `complete`, basis and decision | `Analyzer.site`; `Graph.build` site loop; `storage.split_graph` ordinal rows | Recreate site order and re-adjudicate evidence, not only change the ID. New/removed sites alter ordinal inventory. |
| Raw Jedi mapping `source_sha256`, target `version_id`, raw/error and inferred targets | `Analyzer.map_name`/`query`; site `evidence` and `resolution_decision` | Redo a query unless a complete dependency proof certifies its result against current project membership and definition mapping. Rewrite nested mapped versions only after validating target and absence dependencies. |
| `Result` atoms/reasons/proofs/requirements, `coverage_receipt`, access proofs and traces | `resolve`, `attribute`, `container_slots`, `call_field_effect`, `ReceiverAccess.summary`, `explain`, `adjudicate` | Recompute or explicitly translate every AST identity and verify all `valid_coverage` obligations. `ReceiverAccess.summary` and call-access definition lists carry `version_id`; exported traces and receipts can nest such records. A generic JSON replacement is insufficient. |
| CALLS/REFERENCES/IMPORTS/INHERITS/WRAPS/CONTEXT_ENTERS and CONTAINS edges | `Graph.build` and `add_edge`; SQLite edges, relation query, Neo4j projection | Recompute affected relationships, endpoints, `source_version_id`/`target_version_id`, `site_id`, status, `complete` and `edge_id`; check removed targets and boundary transitions. Other unchanged logical edges still get new IDs when an endpoint version changes. |
| Graph summary and artifact integrity | `Graph.build` (`sites`, counts, budgets, bindings); `storage.split_graph`, `validate_folder`; `neo4j_graph.load_snapshot` fingerprint | Recompute counts, limits/UNKNOWN, dependency bindings, graph-sites/source-files artifacts, checksums and complete snapshot fingerprint before atomic publication. Do not copy an old complete marker. |

The source shows these known version-bearing fields, but it does **not** establish that every nested exported evidence shape can be rebased by a finite field whitelist. Proof receipts may contain nested access/definition paths; their semantics, not just their IDs, must be verified. A schema audit and same-input full-build differential comparison are prerequisites to declaring A's publication rebind complete. Rebinding all public records is O(output size), even if successful dependency-local analysis avoids O(all computation).

## B. Make public version identity file-local

Changing `python_nodes.identity` to derive `version_id` and `Analyzer.site` to derive `site_id` from file bytes would keep unchanged-file IDs stable. It changes a deliberate public contract: `snapshot_scope="repository-capture"` and repository-wide `snapshot_id` currently bind each definition/site to the entire captured repository. The Graph edge IDs, SQLite records, graph-sites payload, Neo4j raw JSON/fingerprint, and clients that interpret version ID as captured repository provenance would change. It would need an explicit new identity/schema version, compatibility/migration rules for retained versions and restore, and separate snapshot provenance carried with every reused proof. Stable file IDs alone do not mean that an unchanged call has a stable target, completeness, or UNKNOWN state. A definition newly appearing in another file can invalidate negative lookup; a caller in another file can change a callee's parameter association. Thus B reduces identity churn but does not solve dependency tracking or Jedi result validity.

**Recommendation:** Preserve the current public identity (A) while first building exact dependency evidence and a conservative invalidation protocol. Avoid B as a shortcut to performance; pursue it only as a separately reviewed public schema change if A's measured rebinding cost dominates. Neither route is presently proven implementable as precise cross-file reuse from existing caches alone.

## Dependency proof needed before either route can skip analysis

For each cached result, record positive source/definition/import reads; negative name/member/import lookups and relevant namespace membership; call candidate admission including syntactic matches, no-atoms/errors/unqueried sites, aliases and callbacks; reverse parameter/registry associations; class construction fallback; field/slot write and implicit-effect obligations; pin/closed-world/config/program versions. Maintain reverse indexes from changes and newly *possible* matches to consumers. A changed/deleted definition must invalidate direct and transitive readers, existing callers, boundaries and inherited/member lookups. A newly added module, export, `__init__.py`, definition or import can turn a prior no-result/external boundary into an internal target; a new call site can change prior parameter/registry outcomes without touching the callee file. A pin change can change `Graph.imported` boundary to a cross-repository target or vice versa. Deletions and renames invalidate both old and new module/name spaces.

Cached `Analyzer.query` observations cannot by themselves prove this closure: they record the observed Jedi names/mappings or `jedi-no-result`/error at a position, but not all searched modules, candidate namespaces, absence predicates, or Jedi's internal dependency graph. `query` also adds `jedi-inference-not-exhaustive` for callable/class/instance observations. The in-memory `candidate_sites` index explicitly treats no-atoms, failures and unqueried sites as admissible; it cannot safely become a negative cross-snapshot index. This conclusion follows from the stored fields and consumers, not an assertion that Jedi could never expose such information through a different integration.

Until complete dependency and negative-lookup evidence exists, any captured input, repository revision/pin, configuration or program change requires `full-capture` graph analysis. Preserve every prior supported candidate and UNKNOWN reason under incremental work; a failed proof expands the invalidation scope or falls back, never silently certifies absence. Verify cold/warm analysis and unrelated-data growth from the public build path, with internal reads/parses and output bytes separately counted; this report is only static diagnosis and makes no performance claim.
