# Bounded dictionary callback plan (read-only review)

The repository-local `code-graph-dependency-change` skill and design contract describe **proposed** support tracking, not shipped behavior. For the stated case, retain the existing catalog definitions of `first` and `second` as callable targets. Give the two dictionary allocations distinct abstract container origins `A` and `B`; bind `alias` to `A`. The exact entries are `(A, 'go')` and `(B, 'go')`, never one shared key-only identity. Source-identified writes `w1: A['go'] = first`, conditional `w2: A['go'] = second`, and any `B['go']` write each retain their own ordered/conditional support. The `alias['go']()` site is a separate stable read/call identity owned by its execution scope. It reads `(A, 'go')` and may target both `first` and `second` after the conditional join; retain the full analyzer's `UNKNOWN` and completeness, rather than asserting a stronger resolution. A projected owner-to-function `CALLS` edge derives from surviving site supports; the assignments or registration are not calls. A repeated loop execution does not multiply static sites.

The `registry_a[key]()` site has a known container `A` but an unknown key: record a **range subscription over A's entries**, candidate supports and uncertainty, rather than inventing an exact `key` entry or connecting it to `B`. If `key` or the container can be unconstrained/escaped, retain the corresponding broader `UNKNOWN` boundary. Include a failed exact-key read or absent-entry membership subscription when applicable; it is necessary to catch a future writer. For supported primitive constants, canonicalize according to Python hash/equality (`True`, `1`, `1.0` share an entry); do not invoke arbitrary project-defined equality or hashing.

On the later captured update, use old snapshot reverse evidence for removal of `w1` to find both consumers of `(A, 'go')`, remove only `w1`'s contribution, and recompute the exact site's target/status and its projected `CALLS` edges. The conditional `w2` can survive, with possible absence/unknown as dictated by full analysis; it must not become an unconditional replacement. Addition of the formerly absent `(A, new_key)` changes A's membership and fans out to the unknown-key range subscriber, and to any old negative exact-key subscriber; it must not invalidate B solely because its key text matches. Traverse changed producer/membership → readers → changed call sites/outputs and any downstream argument/return consumers until target sets, absence, `UNKNOWN`, completeness, fields and provenance stabilize. Index by container/entry and actual support relations; widen or rebuild if alias/equality/context, old evidence, cycles, budget or pins prevent a proof.

The smallest implementation slice is exact known-allocation constant-key dictionary writes/reads, one conditional join and one call-site support relation, with reverse entry and missing-entry membership indexes; add the known-container range subscriber needed for this scenario as a separately gated extension. Reuse `EffectEvent` ordering, phase and conditional signals and current graph site IDs/results. Persist source-site writes, container/entry identities, positive/negative reads, many-to-many supports and coverage/version markers in an immutable SQLite snapshot, with capture rebinding and old-schema fallback. Extend incremental admission only when the evidence is complete and the result equals an independent full build under identical captured inputs; otherwise preserve the current full-analysis fallback. Gate publication integrity, dense reuse and any Neo4j projection/schema change separately. These semantic container, entry, write and call-site records do **not** enter existing module/class/function vector searches or receive automatic embeddings; the existing `first`/`second` function definitions remain ordinary function search nodes.

Minimal validation to implement later: a small captured fixture with A/B both containing `'go'`, alias of A, unconditional first and conditional second writes, exact and unknown-key calls; compare fresh full versus admitted incremental public nodes/edges/site target sets, `UNKNOWN`, completeness and provenance after deleting `w1` and adding a previously absent A key. Check B isolation, surviving second support, missing-key subscriptions, equal primitive keys and source-capture rebinding. Add old-evidence/truncation and failed-candidate-publication fallback cases. Use SQLite `EXPLAIN QUERY PLAN` and internal reverse-lookup read counts while unrelated containers/entries grow; distinguish this from O(N) checksum/serialization/inventory work. Do not claim precise callback behavior beyond the full analyzer's evidence.
