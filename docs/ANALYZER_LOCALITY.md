# Analyzer locality and source indexing

The current Python analyzer takes callable targets directly from Jedi 0.20.1 observations. Explicit call sites use `get_signatures` at the call opening parenthesis; references, imports, bases and implicit decorators use the applicable `infer` query. `map_name` maps a returned source definition to a captured node by exact location. It does not resolve a right-hand side, adjudicate candidates, or invoke a secondary target engine. An empty or failed Jedi observation stays unknown.

The source recorder keeps a separate index of AST sites by execution owner. Preparing a selected owner visits its own sites, records source `goto` bindings, and subscribes to syntactic container reads and writes. Its indexed source-origin graph propagates allocation-site membership and aliases for update scheduling; that membership is candidate source evidence, never a callable target, latest value, or proof of runtime exhaustiveness. Source `goto` locations may identify a producer owner, but they do not change Jedi's inferred targets.

A call site reaches the query bridge directly from graph emission. An eager signature pass and an unused cross-capture lexical certificate no longer run. The same capture still shares its Jedi observations, and an identical Python capture can reuse its verified graph without Jedi queries. The legacy private observation table remains readable; new builds do not populate it with lexical certificates.

The public counters separate target Jedi query entries, cache hits and executions from source `goto` entries, cache hits and executions. Source index entries, owner preparations and owner-site visits expose work otherwise hidden behind output counts. These measurements must distinguish first capture indexing from the work of a selected owner on update. A source origin that cannot be located retains an unknown watch; it must not silently exclude a future writer or promote an unknown call to every function.

Warm and full analyses compare graph semantics and source inputs under the same new snapshot contract. Published raw Jedi observations retain their returned order for diagnosis; their outer candidate order is not a target priority or graph semantic. Snapshot formats from the retired value-flow target certificate are incompatible with source-only coverage on ordinary updates and do not authorize reuse as the new format.
