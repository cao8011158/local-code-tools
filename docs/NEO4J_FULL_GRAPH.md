# Bounded full-size Neo4j projection (Batch 3)

`lct.neo4j_graph` projects an explicitly named, already published SQLite index into a Neo4j namespace/version. SQLite and its manifest remain authoritative. This importer preserves raw node and edge JSON, complete graph/sites evidence, UNKNOWN and external/null endpoints, and source revision identities. It does not parse sources, embed content, change query ranking, or provide incremental synchronization. The existing `docs/NEO4J_SMALL_GRAPH.md` describes the API and CLI; its 500-node/5000-edge and 30-second import limits are superseded here.

Import is conservatively bounded at **50,000 nodes**, **500,000 logical edges**, and **128 MiB of UTF-8 canonical snapshot JSON**. Any one parameter record must fit **1 MiB**; writes use no more than **500 records** and **1 MiB of serialized record parameters** per `UNWIND` query. These are safety ceilings, not throughput or supported hardware promises. The complete graph/sites JSON remains one snapshot property and is subject to the total snapshot bound. `load_snapshot` verifies the manifest, artifact hashes, SQLite integrity and counts before returning raw data. `import_snapshot` independently checks capacity, kinds, duplicate IDs and fingerprint before publishing. Callers should plan Neo4j transaction memory, disk, timeout and payload limits for their environment; very large projects beyond these bounds require a separate design.

The importer prepares bounded parameters before writing and then performs all node, logical edge and native relationship batches in **one transaction**, with a fixed **300-second transaction timeout**. Fixed labels and relationship types come only from whitelists; source IDs and raw JSON remain parameters. Completion is marked only after every batch succeeds. A failure rolls back the scope's records, and the same namespace/version/fingerprint is idempotent; conflicting content is refused. Schema constraints are initialized beforehand and may persist after an import failure. There is no intermediate complete snapshot or multi-transaction publication.

Read limits remain deliberately separate: `get_nodes` and `get_relations` accept at most **500 IDs**, `limit` is at most **5,000** (default 100), and listing/relation reads preserve existing pagination semantics. This projection does not expose an unbounded bulk read API. External and null endpoint edges retain logical `LCTEdge` records; only pairs of indexed nodes have native typed relationships, so native relationship counts do not equal total logical edge counts.

For real-service verification, set `LCT_TEST_NEO4J_URI` (and optionally `LCT_TEST_NEO4J_USER`, `LCT_TEST_NEO4J_PASSWORD`, `LCT_TEST_NEO4J_DATABASE`) then run `pytest -q tests/test_neo4j_bulk_import.py tests/test_neo4j_small_graph.py`. The bulk fixture uses 1,200 nodes and 6,000 edges, checks raw roundtrip, native versus boundary counts, query ID cap, bounded query counts, idempotence, capacity rejection and rollback after a completed edge batch. This synthetic case does not establish business-repository performance or a production capacity guarantee.
