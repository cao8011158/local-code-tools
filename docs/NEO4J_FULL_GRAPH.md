# Bounded Neo4j projection (Batch 3)

`lct.neo4j_graph` projects an explicitly named, already published SQLite version into an explicit Neo4j namespace/version. SQLite and its manifest remain authoritative. Node/edge raw JSON, complete graph/sites evidence, UNKNOWN and external/null endpoints, and source revisions are preserved. There is no parser, embedding, query ranking, or MCP write change.

Input preflight checks the manifest/artifact integrity, node and edge counts, supported kinds, unique IDs, canonical fingerprint, **50,000 nodes**, **500,000 logical edges**, and **128 MiB** total canonical snapshot. A parameter record must fit **1 MiB**; each `UNWIND` batch has at most **500 records** and **1 MiB** serialized JSON. Complete scopes with the same fingerprint return `already_present` before any write-batch preparation; different fingerprints are refused.

The importer claims an `LCTSnapshot` marker using a Neo4j marker write lock, owner token and renewable 60-second lease. A concurrent same-content caller waits up to 10 seconds and returns `already_present` if publication finishes; otherwise it reports an active writer. Every batch and cleanup transaction locks and checks the marker owner and incomplete state. An expired lease can be claimed by a retry, fencing the old writer. Schema constraints cover snapshot, node, edge, and `(namespace,version,kind,ordinal)` metadata chunk identities.

Nodes, logical edges, native relationships, and metadata chunks commit in separate bounded transactions with a 300-second per-transaction timeout. Graph and source JSON are stored as UTF-8-safe **256 KiB** `LCTChunk` properties, not one large marker property. The marker records expected node, edge, native relationship counts and metadata hashes. Before publication the importer compares each persisted node, edge, indexed field, native relationship, and metadata chunk against the input, including identity, content, endpoints, kinds and extra records. Verification streams records with a bounded driver fetch size. The candidate is immutable in the validating state; final publication sets `complete=true` in a small fenced transaction. Reads reject incomplete scopes. Legacy complete snapshots with `graph_json`/`source_json` remain readable and idempotent.

An ordinary failure leaves incomplete data hidden and releases the owner. A crash leaves the owner until the lease expires. Retry with the **same input** claims the marker, deletes that candidate's scoped relationships, chunks, edges and nodes in bounded commits, then imports from the start; it does not resume a partially completed batch. Cleanup never deletes a complete scope, another namespace/version, or another active owner's records. A failed retry remains hidden. No public cleanup or MCP write operation is exposed. Query limits remain 500 IDs and 5,000 result rows, with existing pagination behavior.

Real-service tests use `LCT_TEST_NEO4J_URI` and optional user/password/database variables. Run `pytest -q tests/test_neo4j_bulk_import.py tests/test_neo4j_staged_import.py tests/test_neo4j_small_graph.py`. Synthetic tests exercise batch bounds, incomplete reads, retry, conflicts, tampering, Unicode chunk boundaries and an 8 MiB graph metadata roundtrip. These bounds are safety ceilings, not production throughput or full business-repository capacity guarantees.

## Optional certified dictionary value projection

A snapshot with validated `value_flow_schema=1` and `certified-dictionary-v1` coverage projects as `native-value-v3`. Its canonical fingerprint binds the original four v2 fields **and** the sorted `value_nodes`, `value_edges`, and `value_reads` arrays. The four-field v2 fingerprint remains unchanged for other snapshots, which report `value_projection=unprojected-partial`; zero value records in such a scope do not assert an empty dictionary flow. A complete v2 scope cannot be upgraded in place to v3: import under a fresh version or namespace.

Scoped `LCTValue` nodes have typed `Container`, `Entry`, `Binding`, `Write`, and `Read` labels. Each value support edge has an `LCTValueEdge` raw record and one typed native relationship. A callable endpoint points to the existing `LCTNode:Function`, without creating a second function or adding value nodes to the searchable/vector catalog. `READS` raw evidence includes the read consumer repository and path. A missing-key entry is an address with `present=false`, not a runtime key; its read subscription is retained. Alias/import bindings point to the same container identity. Full raw graph/sites and UNKNOWN evidence remain in their existing chunks and code records.

The marker records separate code, value-node, value-edge, value-read counts; `native_count` covers both code and value relationships. All value records, endpoints, subscriptions, native relationships, counts and metadata are verified while incomplete before one fenced final marker update. Failed candidates stay hidden; retry clears scoped partial value and code records. Code relation queries remain limited to code relationship kinds under either v2 or v3. Known value IDs and callable IDs traverse native value adjacency through the indexed `LCTValue`/`LCTNode` identities and return bounded pages. This is a projection of the existing certified narrow subset, not a broader Python analysis certificate. Existing complete legacy scopes remain readable under their prior schema.
