# Verified captured source snapshots

An opt-in repository entry can set `"source_manifest": "source-manifest.json"` alongside its normal `name`, `path`, `code_roots`, and `exclude_files`. The path is relative to that repository's local root. This input is for source files captured from pinned GitHub file/blob responses when no local Git checkout is available. It does not claim that the local directory is a Git working tree or independently prove that the recorded commit is authentic. Acquisition must verify GitHub metadata and capture the actual root tree ID before writing the manifest.

Schema 1 contains `repository`, 40-character lowercase hex `head` and `tree`, `branch: "main"`, `provenance: "github-pinned-tree"`, `selected_scope`, and `files`. Each file entry has a canonical relative POSIX `path`, Git blob SHA-1 (`git_blob_sha`), SHA-256 (`sha256`), and byte count (`bytes`). `selected_scope` exactly records the configured `code_roots`, `include_tests`, and `exclude_files`, plus `docs: true`, `root_files: [".py", ".md"]`, and `excluded_directories` equal to the inventory's sorted exclusions. See `tests/test_source_snapshot.py` for a synthetic local fixture; its hashes do not assert remote provenance.

At build and explicit freshness refresh, every declared byte sequence is checked against length, SHA-256 and Git blob SHA-1. The bounded source selection is checked for undeclared eligible additions and missing/out-of-scope entries. Paths with traversal, absolute paths, backslashes, or symlink components are rejected. Ordinary query retrieval reads the published index; it does not walk this captured directory. An ordinary repository without `source_manifest` continues using Git metadata and its existing inventory behavior.

The index repository metadata retains the recorded `head` and `tree`, a manifest SHA-256 and explicit status `verified captured source snapshot (not Git working tree)`. The same source fingerprint and captured source paths continue to drive published versions, search, graph results, and portable restore. A subsequent edit requires a new verified manifest and matching file set before another build.
